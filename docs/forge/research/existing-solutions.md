# Готовые решения — разведка (Forge discovery)

Направление: что уже существует и закрывает часть задачи цифровых чек-листов
(редактор с секциями и библиотекой блоков, публичное заполнение по QR без
авторизации, генератор QR/печать A4, версионирование чек-листов).

Стек продукта: Next.js (App Router, TS), PostgreSQL, Drizzle ORM, Tailwind.

Пишу находки по одной, по мере поиска. Для каждой: ссылка, лицензия,
живость, что берём/почему не берём.

---

## 1. Движки форм и конструкторы чек-листов с версионированием

### SurveyJS (survey-library + survey-creator)

- **Рендерер форм**: https://github.com/surveyjs/survey-library — MIT,
  живой (последний пуш сегодня, 2026-09-05), 4867 звёзд. Прочитан README
  целиком. Рендерит формы из JSON-схемы (секции = "pages"/"panels",
  типы вопросов, валидация, условная логика). Хранение — просто JSON,
  что и куда сохранять — решает вызывающий код.
- **Визуальный конструктор (drag-and-drop builder)**:
  https://github.com/surveyjs/survey-creator — лицензия **НЕ MIT**: файл
  LICENSE (прочитан целиком,
  https://github.com/surveyjs/survey-creator/blob/master/LICENSE) —
  коммерческий EULA от Devsoft Baltic OÜ, платная лицензия на
  разработчика для бизнес-использования. Значит именно тот компонент,
  который ближе всего к нашему "редактору чек-листов", свободно
  использовать нельзя.
  - **Вывод**: рендерер (survey-library) можно было бы взять для показа
    публичного экрана заполнения, но у нас входные данные проще (да/нет,
    число, текст, критичность), а хочется полного контроля над
    построчным вводом с клавиатуры и вставкой из буфера — то, чего
    SurveyJS из коробки не даёт (это конструктор с формами-полями, а не
    построчный текстовый ввод). Тянуть тяжёлую библиотеку (survey-core
    ~ несколько сотен КБ) ради рендера да/нет/число/текст неоправданно.
    **Своё**: пишем свой рендерер на Tailwind под 3 типа ответов — это
    тривиальная задача, а конструктор всё равно не переиспользовать
    (закрытая лицензия). SurveyJS не берём.

### form.io (formio.js + formio server)

- https://github.com/formio/formio.js — **MIT**, живой (пуш
  2026-09-04), 2086 звёзд. "JavaScript powered Forms with JSON Form
  Builder" — в отличие от SurveyJS, сам билдер тут MIT.
- https://github.com/formio/formio — серверная платформа форм, лицензия
  **Open Software License 3.0** (OSL-3.0) — копилефт-лицензия с
  особенностями (модификации веб-сервиса должны публиковаться), живой
  (пуш 2026-09-02), 2314 звёзд.
  - **Просмотрено по заголовкам** (README, не всё целиком) — оценка по
    структуре репозитория (`src/`, docs на formio.com).
  - **Вывод**: formio.js (билдер, MIT) теоретически годится как основа
    JSON-схемы форм, но это полноценный движок форм общего назначения
    (сложные условия, много типов компонентов, свой рантайм) — тяжелее,
    чем нужно для 3 типов ответов + секции + библиотека блоков.
    Заводить формио как зависимость means подстраивать нашу модель
    "секция → пункт → тип ответа → критичность" под их модель
    компонентов, что сложнее, чем написать свою схему на 4 таблицы
    Drizzle. **Не берём**, но держим в уме как референс JSON-схемы форм
    с вложенными компонентами, если понадобится более сложная логика
    условных пунктов в будущем.

### ODK / KoboToolbox / Enketo (экосистема сбора данных в полях)

- https://github.com/getodk/central — сервер ODK, **Apache-2.0**, живой
  (пуш 2026-09-04), 223 звезды.
- https://github.com/getodk/collect — Android-клиент, лицензия Other
  (по факту Apache-подобная с доп. условиями), живой, 786 звёзд —
  нерелевантно (нативное Android-приложение, не веб/React).
- https://github.com/enketo/enketo-express — веб-рендерер форм ODK
  (XForms → веб), Apache-2.0, но **repo заархивирован**
  (`archived: true`, последний пуш 2023-11-29) — мёртвый проект,
  не берём.
- https://github.com/kobotoolbox/kpi — сервер KoboToolbox с
  "question library" (переиспользуемые вопросы/блоки — концептуально
  близко к нашей "библиотеке переиспользуемых блоков"), AGPL-3.0,
  живой (пуш 2026-09-04), 181 звезда. Просмотрено по заголовкам README,
  не читал код целиком.
  - **Вывод**: вся экосистема ODK/Kobo заточена под офлайн-сбор данных в
    полевых условиях (XForms, ODK XML, ODATA) — модель тяжелее и старше
    нашей задачи, стек Python/Django + Angular, не Next.js/Drizzle.
    AGPL/OSL лицензии сервера означают риск copyleft-обязательств при
    встраивании. Концепция "библиотеки переиспользуемых вопросов" у
    kpi подтверждает, что паттерн разумный, но код брать не будем —
    несовместимый стек и лицензии. **Не берём код, берём только
    паттерн** (общая библиотека блоков с редактированием в одном месте
    — см. раздел 5 про схему хранения).

### Formbricks

- https://github.com/formbricks/formbricks — "Open Source Qualtrics
  Alternative", лицензия **Other** (не MIT — нужно проверить точный
  текст, ядро под AGPL-подобной с коммерческим переходом), живой (пуш
  2026-09-05, сегодня), 12893 звезды, Next.js + Prisma в стеке.
  Просмотрено по заголовкам (org page + README), не читал схему БД
  целиком.
  - **Вывод**: Formbricks — это продукт опросов/фидбека (NPS, in-app
    surveys), а не чек-листов, ориентирован на конечного пользователя
    сайта, а не на сотрудника с QR-станцией. Стек Next.js близкий, но
    доменная модель (опросы, таргетинг, сегменты) не совпадает с нашей
    (станции, критичные пункты, версии). Лицензия "Other" требует
    отдельной проверки, если решим смотреть глубже. **Не берём** —
    несовпадение домена перевешивает совпадение стека.
