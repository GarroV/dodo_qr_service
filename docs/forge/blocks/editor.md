# Block: editor

## Назначение

Редактор чек-листов — главный экран продукта. Задача блока не «дать возможность создать чек-лист», а сделать так, чтобы чек-лист из двадцати пунктов заводился за минуты.

## API-контракт

```ts
createChecklist({ stationId, title, window }); getDraft(checklistId)
saveDraft(checklistId, sections: Section[])
publish(checklistId): Promise<ChecklistVersion>
duplicateChecklist(checklistId, { toStationId? }): Promise<string>
removeChecklist(checklistId): Promise<'deleted' | 'archived'>   // стереть или снять с работы — по наличию заполнений
previewRemoval(checklistId): Promise<RemovalPreview>            // что произойдёт, для экрана подтверждения
parsePastedList(text: string): Item[]      // строки → пункты, пустые строки и маркеры списка отброшены
```
Формат `sections` — единственный контракт с блоком `fill`, описан в плане.

## Зависимости

`data`, `auth`

## Definition of Done блока

1. Enter в поле пункта создаёт следующий и ставит в него курсор; Alt+↑/↓ переставляют пункт.
2. Вставка 20 строк из буфера превращается в 20 пунктов за одно действие; маркеры списка и нумерация отброшены, пустые строки пропущены.
3. Тип ответа по умолчанию «да/нет»; число принимает границы диапазона; критичность переключается по месту.
4. «Сохранить черновик» и «Опубликовать» — разные действия: публикация создаёт версию, черновик остаётся черновиком.
5. Дублирование чек-листа копирует секции и пункты, но не историю заполнений.
6. Предпросмотр открывает тот же экран, что видит сотрудник, с данными черновика.
7. Экран совпадает с эталоном `docs/forge/design/screens/editor.html`.

## Решения, принятые внутри блока

| Решение | Почему |
|---|---|
| Опубликованная версия хранит секцию блока библиотеки как `source: { blockId }` с развёрнутыми пунктами | Снимок — это пункты (D002), а происхождение секции нужно библиотеке: без него `listUsages` (T030) не сможет сказать, сколько опубликованных версий затронет правка блока |
| Публикация освежает ссылки в черновике и только потом зовёт `publishVersion` | Обратный порядок означал бы правку уже созданной версии, а версии неизменяемы. Черновик — единственная мутируемая строка в этой цепочке |
| Пункт без названия пропускается разбором, а не роняет сохранение | Пустая строка внизу списка — обычное состояние редактора: методист нажал Enter и ещё не напечатал текст |
| Пустой чек-лист не публикуется (`nothingToPublish`) | Опубликованная пустая версия — это открытый по QR экран без единого пункта, и понять это можно только на кухне |
| Окно «без ограничения» записывается как `00:00–24:00` | Равные границы запрещены базой (T057), а `24:00` — законное значение `time` в PostgreSQL, делающее условие выбора версии истинным в любую минуту |
| Окно выбирается из трёх готовых вариантов, а не вводится временем | Так в эталоне, и это меньше касаний: у чек-листа станции по сути три окна. Уже записанное нестандартное окно показывается отдельным пунктом списка, чтобы открытие чек-листа не переписало его молча |
| Alt+стрелки переставляют пункт только внутри секции | Пункт, уехавший в соседнюю секцию от одного нажатия, для методиста исчезает: он смотрит на своё место в списке. Требование блока — «переставляют пункт», и оно выполнено без этого риска |
| Вставка в пустой пункт занимает его место | Иначе после вставки списка в только что созданную Enter'ом строку в чек-листе остаётся дырка |
| Тексты пунктов пишутся на языке интерфейса, второй язык не затирается | У методиста нет переключателя языка контента (его нет и в эталоне), а терять уже введённый второй язык нельзя |
| Каркас админки (левое меню) продублирован из блока `catalog`, а не переиспользован | Границы модулей запрещают `editor` зависеть от `catalog` (`.dependency-cruiser.cjs`), а общего места для каркаса в продукте пока нет. Разметка скопирована один в один; правильное место для него — блок `core`, это вынесено наверх диспетчеру |
| Разделы, которых в продукте ещё нет (библиотека, заполнения, QR), показаны неактивными надписями | Ссылка вела бы в 404. Так же поступает `catalog` в своём каркасе |
| У сквозных сценариев своя база `dodo_qr_e2e_<метка копии>` | Рабочую снесла бы подготовка схемы, тестовую посреди прогона пересоздаёт vitest, а экраны редактора читают и пишут настоящие данные |
| Тексты редактора уходят в браузер провайдером `next-intl` | Клиентская часть большая и с числительными («4 пункта», «используется ещё в 6 чек-листах»); пробросить готовые строки нельзя — количество меняется прямо на экране |
| «Удалить» ведёт на отдельный экран подтверждения, а не удаляет сразу | Последствие зависит от истории и его надо назвать заранее: чек-лист без заполнений стирается целиком, а чек-лист, по которому уже заполняли, только уходит из работы (`archived_at`, миграция 0005) — заполнения хранят снимок пунктов, которые видел сотрудник (принцип 3, D002). «Удалить» и «убрать из работы» слишком разные вещи, чтобы выясняться после нажатия. Заодно экран работает без JavaScript, как остальные формы, — всплывающее «вы уверены?» без JS не работает вовсе |

## Журнал работы

| Задача | Кем | Что сделано |
|---|---|---|
| T019 | сам | Черновик чек-листа: `createChecklist` заводит его сразу с черновиком (пустая секция и пустой пункт — курсор попадает в поле, а не в пустой экран), `saveDraft` пишет разметку вставкой с разрешением конфликта по частичному индексу «один черновик», `updateChecklist` ведёт название, станцию и окно, `loadEditor` отдаёт экрану всё за один заход. Здесь же разбор входа на границе (`validation.ts`) и списки для экранов. Ядро блока и работа с базой делегированию не подлежат |
| T020 | сам | Клавиатура: Enter создаёт следующий пункт сразу за текущим и уводит в него курсор, Alt+↑/↓ переставляют пункт внутри секции и оставляют курсор на нём. Правила вынесены в чистые функции (`editing.ts`, 20 тестов), связка с настоящими событиями браузера — в сквозном сценарии. Главное обещание блока, поэтому сам |
| T021 | исполнитель | Разбор вставленного из буфера списка (`paste.ts`): чистая функция с готовым контрактом и перечнем случаев, без базы — ровно тот случай, когда задача обязана уходить исполнителю. Сдал 18 тестов зелёными, с красным прогоном до кода и проверкой порчей |
| T021 — приёмка | сам | Разобрал код исполнителя и прогнал свою пробу на краях: дробное число в начале строки (`1.5 кг муки`), строка Excel из нескольких колонок, чекбокс Markdown без маркера списка. Все три прошли; случаи добавлены в набор постоянно (21 тест) |
| T022 | сам | Типы ответов и критичность по месту: «да/нет» по умолчанию, число с границами, текст. Смена типа с числа снимает границы — невидимое значение не должно уезжать в базу. Строка пункта по эталону, сохранение проверено сквозным сценарием |
| T023 | сам | Публикация: `publish` освежает вставленные блоки библиотеки в черновике и зовёт `publishVersion` из `data`. Ключевое правило продукта (D002) делегированию не подлежит. **Отрицательный прогон:** публикация без освежения ссылок роняет тест снимка (`expected [ { id: 'item-санитария', …(3) } ] to strictly equal [ { id: 'item-санитария-2', …(3) } ]`), файл восстановлен копией |
| T024 | исполнитель | Дублирование чек-листа (`duplicate.ts`) по готовому контракту и образцу `drafts.ts`: механическая работа без миграций и без правки чужих блоков. Сдал 19 тестов зелёными, с красным прогоном и порчей (5 падений на двух внесённых дефектах) |
| T024 — приёмка | сам | Разобрал код и написал свой сквозной тест на связку с публикацией: копия чек-листа, у которого есть и черновик, и опубликованная версия с заполнениями, берёт черновик, заполнений не наследует и публикуется на свою станцию (`duplicate-publish.test.ts`) |
| T025 | исполнитель | Предпросмотр «как это увидит сотрудник» по эталону `fill.html` из данных черновика. **Временный:** сохранения ответов нет, настоящий экран заполнения принесёт блок `fill`; на самом экране об этом сказано плашкой. Исполнитель нашёл и починил свой же дефект: стартовый пустой пункт показывался пустой строкой вместо «в черновике пока нет ни одного пункта» |
| T026 | сам + исполнитель | Экран редактора по эталону — сам (состояние, клавиатура, секции, правая колонка); список чек-листов, экран заведения и каркас админки — исполнитель по эталонам `templates.html` и `editor.html`: разметка по готовому эталону с готовыми данными и текстами механическая |
| T026 — сверка с эталоном | сам | Экран открыт в живом браузере рядом с эталоном (безголовый Chrome по отладочному протоколу, снимки обоих). Сверка нашла то, чего не видели ни типы, ни тесты: время публикации приходило из базы строкой и такой же попадало в правую колонку (на регрессию есть тест); название блока библиотеки бралось «первым ключом» JSONB и в русском интерфейсе показывалось по-английски; не хватало «Свернуть», «Открыть блок», ссылки «Вся» и кнопки «Вставить блок из библиотеки»; у списков не было стрелки эталона; счётчик пунктов торчал на экране лишней цифрой |
| Приёмка работы исполнителей | сам | Каркас админки оказался скопирован дважды внутри блока (мой `AdminNav` и меню внутри `AdminShell` исполнителя) — сведён в один компонент: две копии одного меню разъехались бы на первой же правке. Клавиатура проверена мной отдельно от сквозных сценариев: безголовый Chrome, `Input.dispatchKeyEvent` и настоящий буфер обмена (`commands: ["paste"]`) |
| Проверка порчей сквозных сценариев | сам | Обработка Enter отключена одной правкой — падают 2 сценария клавиатуры с внятной причиной (`expect(locator).toHaveCount(expected) failed, unexpected value "1"`), восстановление копией возвращает 6 зелёных |
| Покрытие | сам | Серверные действия не покрывались вовсе: файл с `"use server"` нельзя разобрать по частям. Разбор формы и выбор кода отказа вынесены в `action-input.ts` и покрыты тестами — путь отказа единственное, что методист видит вместо своей работы |
