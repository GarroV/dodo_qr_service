# Block: demo

## Назначение

Демонстрационный контур и запуск продукта на локальной площадке: чтобы показать коллегам, ничего не заводя руками.

## API-контракт

```
npm run seed:demo     # идемпотентный сид, повторный запуск не плодит дубликаты
```
Данные демо — английские (правило проекта), отдельная демонстрационная страна, не смешивается с рабочими данными.

## Зависимости

`catalog`, `editor`, `fill`, `feed`

## Definition of Done блока

1. Сид создаёт демонстрационную страну, две пиццерии, станции с кодами, три чек-листа с секциями и переиспользуемым блоком и десяток заполнений, включая одно с проваленным критичным пунктом.
2. Повторный запуск сида возвращает контур в исходное состояние и не плодит дубликаты — проверено двойным прогоном.
3. Продукт поднимается на локальной площадке одной командой, адрес открывается в браузере.
4. Сквозной сценарий MVP проходит на поднятом продукте целиком: от создания чек-листа до появления заполнения в ленте.
5. Демонстрационные данные не попадают в рабочую страну.

## Устройство блока

| Файл | Что внутри |
|---|---|
| `src/blocks/demo/model.ts` | Форма контура: страна, пиццерии, станции, блоки библиотеки, чек-листы с версиями, заполнения. Времени в описании нет — только смещения назад от опорного момента |
| `src/blocks/demo/dataset.ts` | Сам контур: английские данные с постоянными опознавателями. Только данные, без запросов |
| `src/blocks/demo/answers.ts` | Ответы заполнения собираются из разметки версии, а не перечисляются рядом с ней |
| `src/blocks/demo/seed.ts` | `seedDemo()`: одной транзакцией снимает прошлый контур и заводит его заново |
| `src/blocks/demo/index.ts` | Публичный вход блока |
| `scripts/seed-demo.mjs` | `npm run seed:demo` — запуск сида с печатью ссылок станций |
| `scripts/src-resolve-hook.mjs` | Хук разрешения импортов: Node сам не знает ни псевдонима `@/`, ни импортов без расширения |
| `scripts/up` | `npm run up` — одна команда: база, миграции, контур, сборка, запуск |
| `scripts/mvp-smoke.mjs` | Сквозной смоук MVP в живом браузере со снимками; параметризован адресом |

## Решения, принятые внутри блока

| Решение | Почему |
|---|---|
| Идемпотентность устроена как «снять своё и завести заново», а не «досоздать недостающее» | Досоздание требует сравнивать каждую строку с описанием и разбирать частичные расхождения — ровно тот код, который тихо расходится с данными. Опознаватели контура постоянны, поэтому снятие точечное и чужой строки не касается |
| Заполнения снимаются по СТАНЦИИ контура, а не только по своему опознавателю | На показе по демо-коду заполняют по-настоящему; такая запись держала бы версию внешним ключом, и второй прогон сида падал бы вместо обновления контура |
| Времени в описании контура нет — только смещения назад от опорного момента | Иначе демо через месяц показывает ленту месячной давности, а два прогона нельзя сравнить строка в строку |
| Два чек-листа одной станции закрывают сутки целиком | Демо обязано открываться по QR в любой час: чек-лист с утренним окном вечером не открылся бы, и продукт выглядел бы сломанным |
| Данные демо — только английские, ключ `en` единственный | Правило проекта (конституция, «Демонстрационный режим»). Русское устройство увидит английский текст: `pickText` откатывается к первому имеющемуся языку |
| Запуск сида идёт через хук разрешения импортов, а не отдельной копией запросов в `.mjs` | Node умеет исполнять TypeScript, но не знает псевдонима `@/` из tsconfig. Без хука сид пришлось бы писать мимо слоя доступа — второй набор запросов к базе, который разъедется со схемой |
| Смоук MVP — отдельный сценарий с параметром адреса, а не ещё один файл в `e2e/` | Он обязан гоняться по ПОДНЯТОМУ продукту, в том числе после раскатки на площадку (T079), а `e2e/` поднимает свой сервер и свою базу |

## Журнал работы

| Задача | Кем | Что сделано |
|---|---|---|
| T049 (сид) | сам | `model.ts`, `answers.ts`, `seed.ts` и `scripts/seed-demo.mjs`: описание контура, сборка ответов из разметки версии, снятие прошлого контура и вставка нового одной транзакцией. Логика идемпотентности и границы «своё/чужое» — не механическая работа, поэтому делал сам. **Отрицательный прогон:** снятие контура отключено (`removed = 0`) — упало 7 из 8 проверок сида, первой же `duplicate key value violates unique constraint "countries_pkey"` |
| T049 (данные) | исполнитель | Само содержимое контура (`dataset.ts`): страна `Demoland`, две пиццерии, пять станций с кодами, блок библиотеки `Food safety basics` в двух чек-листах, три чек-листа (у одного архивная версия и опубликованная), 26 пунктов, 12 заполнений. Отдано исполнителю по всем четырём условиям: контракт готов (типы `model.ts` + `dataset.test.ts` как приёмка), работа механическая, миграций и доступа не касается, объём не мелочь |
| Приёмка работы исполнителя | сам | Проверял своими руками, а не по отчёту: перечитал файл целиком и прогнал **свой** разбор контура отдельным сценарием. Тесты исполнителя были зелёные, но нашёлся настоящий дефект: **пять заполнений из двенадцати отвечали на пункт свободного текста пустой строкой**. Продукт таких ответов не создаёт вовсе — `isAnswered` в блоке fill считает текст из одних пробелов НЕотвеченным пунктом, — то есть на карточке заполнения строка «Notes for the day shift» показывалась бы пустой и читалась как «поле не сохранилось». Дыра была в моём собственном контракте: `answersFor` молча подставлял `""`. Закрыто с двух сторон: `answersFor` теперь падает, если у версии есть пункт свободного текста, а заметка не задана (тест на это написан до правки и падал), и всем пяти заполнениям дописаны английские заметки |

## Как продукт живёт на площадке MUSPELHEIM

> Заведено 07.09.2026 (D038, D043, D046). Раскатка выполняется только по явному «да» владельца.

Папка на площадке — `C:\projects\dodo_qr_service`, клон этого репозитория. Своё имя стенда
в Docker (`COMPOSE_PROJECT_NAME=dodo-qr`), приложение на порту 3100, база на `127.0.0.1:5455`
и наружу НЕ публикуется: порт 5433 там занят чужим проектом, а публичной точке записи внешняя
база не нужна. На контейнере базы стоит метка `backup.pgdump=true` — по ней её забирает ночной
бэкап площадки (03:30, ретеншн 14 дней).

Секреты площадки свои, не демонстрационные из `.env.example`: пароль кабинета, секрет подписи
сессии и пароль базы. Файл `.env` лежит только на площадке и в git не попадает.

Наружу продукт отдаёт отдельный туннель Cloudflare (`C:\bootstrap\cloudflared.exe`), продукт
живёт на корне своего адреса. Публиковать его на пути порта Tailscale нельзя, пока не закрыта
T088: обычные ссылки между экранами базового пути не знают.

Два процесса держатся задачами планировщика, а не SSH-сессией (иначе `sshd` убивает дерево
процессов при выходе):

| Задача | Что делает |
|---|---|
| `dodo-qr-start` | `npm run start` — продукт на порту 3100, журнал в `run.log` |
| `dodo-qr-tunnel` | `cloudflared tunnel --url http://localhost:3100`, журнал в `tunnel.log` |

Порядок обновления продукта на площадке: `git pull` → `npm ci` (если менялись зависимости) →
`npm run build` → остановить процесс продукта → `schtasks /Run /TN dodo-qr-start`. Пересборка
обязательна при смене любого значения окружения: значения запекаются в сборку (D033).

Проверка после обновления — одной командой с машины разработчика:

```bash
node scripts/mvp-smoke.mjs --url <публичный адрес> --password <пароль кабинета> --timeout 90000
```

Шаг ожидания задаётся флагом `--timeout`: через туннель ответы идут медленнее, и значения по
умолчанию не хватает. Смоук оставляет после себя данные с именами `Smokeland …` — их нужно
удалять из демо-контура, иначе они копятся в справочнике.
