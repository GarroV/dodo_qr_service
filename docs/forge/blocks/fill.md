# Block: fill

## Назначение

Публичный экран заполнения по QR — единственная часть продукта, доступная без входа. Здесь считается каждое касание.

## API-контракт

```
GET  /s/<код станции>     → опубликованная версия по станции и окну времени
POST /s/<код станции>     → заполнение { answers, startedAt }
```
Ответ не содержит ничего, кроме самого чек-листа: ни истории станции, ни списка чек-листов, ни сведений о пиццерии сверх названия (D021). Частота отправок с одного кода ограничена.

## Зависимости

`data`, `editor`

## Definition of Done блока

1. Сканирование QR открывает нужный чек-лист без единого касания сверх сканирования.
2. Язык интерфейса и текстов пунктов берётся из языка устройства, с откатом на язык страны и далее на русский.
3. Проваленный критичный пункт требует комментарий и не даёт отправить без него; комментарий появляется сразу под пунктом, не отдельным экраном (D018).
4. Числовой пункт принимает значение и показывает, попало ли оно в диапазон, но не блокирует отправку.
5. Кнопка отправки неактивна, пока есть незакрытые пункты, и говорит, сколько их осталось.
6. Неизвестный или перевыпущенный код даёт понятный отказ, а не пустой экран и не чужой чек-лист.
7. Обрыв связи при отправке не теряет введённое: ответы остаются на экране, отправка повторяется.
8. Перебор кодов не отдаёт ничего, кроме отказа — отдельный тест.
9. Заполнение пишется на ту версию, что была отдана клиенту, даже если за это время опубликовали новую.
10. Экран работает на ширине 375 px, зоны нажатия не меньше 44 px, горизонтальной прокрутки нет.
11. Экран совпадает с эталоном `docs/forge/design/screens/fill.html`.

## Журнал работы

Волна: один блок (`fill`), исполнителей внутри блока — двое. Остаток окна подписки
на момент запуска исполнителей — израсходовано 75% недельного окна; поэтому коммит
идёт после каждой закрытой задачи, чтобы обрыв стоил одной задачи, а не блока.

| Задача | Кем | Что сделано |
|---|---|---|
| T038 | сам | Цепочка языков экрана: язык устройства → язык страны пиццерии → русский (`locale.ts`). Своя функция вместо `pickLocale` блока core — та отвечает одинаково на «телефон просит английский» и «телефон просит язык, которого у нас нет», а экрану заполнения эти случаи надо различать. Тем же файлом выбор текста пункта по цепочке. **Отрицательный прогон** — ниже, вместе с остальными |
| T037 (правила) | сам | `station.ts`: что отдаётся по коду — версия, название пиццерии, название станции, язык страны, и ничего больше. Три исхода: `unknown-code`, `no-checklist`, `ok`. Правило выбора версии по окну и часовому поясу не переписано — вызывается `getPublishedVersionForStation` блока `data`. Отдельно `findStationVersion(code, versionId)`: версия принимается, только если её замороженная станция — станция этого кода. Без этой проверки один живой код с наклейки позволял бы писать заполнения в историю любой станции сети (`saveSubmission` выводит станцию из версии). **Отрицательный прогон:** проверка принадлежности снята — тест «не отдаёт версию чужой станции» упал (`expected { …(3) } to be null`) |
| T039/T040 (правила) | сам | `answers.ts`: что считается отвеченным пунктом, сколько осталось, когда открывается кнопка. Провал считается не своим правилом, а `isFailed` блока `data` — иначе экран сотрудника и лента управляющего разошлись бы в том, что невыполнено. Проваленный критичный пункт без комментария закрывает отправку; число вне диапазона отправку не закрывает (критерий 4). **Отрицательный прогон:** требование комментария отключено — упали три теста (`expected [] to strictly equal [ 'c' ]`, `expected true to be false`, `expected [] to strictly equal [ 'n' ]`) |
| T042 (правила) | сам | `validation.ts` — схема тела отправки на границе (типы, длины, пределы; наружу выходит новый объект, поля входа дальше не идут) и сверка ответов со снимком версии: чужой пункт, повтор, чужой тип значения и проваленный критичный без комментария отбиваются сервером, а не только кнопкой. `rate-limit.ts` — свой счётчик частоты (границы модулей запрещают `fill` зависеть от `auth`; там к тому же считаются неудачи, а здесь все обращения). **Отрицательный прогон:** отказ научен продлевать окно и снят потолок числа ключей — упали три теста (`expected false to be true` дважды, `expected 50 to be 3`) |
